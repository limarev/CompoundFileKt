# CompoundFileKt

Kotlin-first Android library for incrementally reading and creating Microsoft
Compound File Binary (CFB/OLE2) containers.

- Android minSdk 24
- CFB version 3 and version 4
- caller-owned `SeekableByteChannel` inputs and outputs
- bounded-memory stream reads
- explicit temporary-file or in-memory stream spooling during creation
- scoped, mode-safe Kotlin APIs
- exact Unicode directory-entry names

The planned Maven coordinate is:

```kotlin
implementation("io.github.limarev:compound-file-kt:<version>")
```

## Read

```kotlin
val primary = CompoundFile.open(source) {
    val dataSpaces = requireNotNull(openStorage("\u0006DataSpaces"))
    val transformInfo = requireNotNull(dataSpaces.openStorage("TransformInfo"))
    val transform = requireNotNull(transformInfo.openStorage("\u0009DRMTransform"))
    requireNotNull(transform.openStream("\u0006Primary"))
        .use { it.readBytes() }
}
```

Large streams can be copied incrementally:

```kotlin
CompoundFile.open(source) {
    openStream("EncryptedPackage")?.use { it.copyTo(destination) }
}
```

## Create

```kotlin
CompoundFile.create(
    destination,
    CfbVersion.V3,
    CfbSpoolingPolicy.TemporaryFiles(context.cacheDir),
) {
    createStream("EncryptedPackage") {
        encryptedContent.copyTo(this)
    }
    createStorage("\u0006DataSpaces") {
        createStream("Version") {
            write(versionBytes)
        }
    }
}
```

### Spooling policy

Spooling is the temporary accumulation of logical stream data before the writer
calculates the CFB sector layout and emits the final container. Every create call
must choose a policy explicitly. Use `TemporaryFiles(directory)` for bounded heap
usage, or `InMemory` when the application must not create temporary files:

```kotlin
CompoundFile.create(
    destination,
    CfbVersion.V3,
    CfbSpoolingPolicy.InMemory,
) {
    createStream("EncryptedPackage") {
        encryptedContent.copyTo(this)
    }
}
```

`InMemory` retains all logical stream content on the heap until the container is
finalized. It prevents temporary-file I/O by the writer, but does not change
where the caller-provided destination stores the completed container. For a
fully memory-only operation, the destination must also be a memory-backed
`SeekableByteChannel`.

Caller-provided channels remain open. Their position after an operation is
unspecified. Read resources and writable DSL receivers are valid only inside
their enclosing block.

## Build and test

```shell
./gradlew testDebugUnitTest assembleRelease
```

The test suite includes strict cross-implementation fixtures generated by
[OpenMcdf](https://github.com/ironfede/openmcdf). The helper under
`tests/openmcdf-interop` verifies CompoundFileKt output with OpenMcdf and is
test-only; it is not included in the Android artifact or production toolchain.
The V3 and V4 fixtures cover stream sizes immediately around the 64-byte mini
sector, 512-byte V3 sector, and 4096-byte mini-stream cutoff boundaries.

The normative API and behavior contract is maintained as an OpenSpec master
specification in `openspec/specs/compound-file/spec.md`.
